# Post Explorer

Flutter-приложение для просмотра, поиска и создания постов. Данные берутся из тестового API [JSONPlaceholder](https://jsonplaceholder.typicode.com). Состояние управляется через **Bloc** (`flutter_bloc`).

## Запуск

```bash
flutter pub get
dart run build_runner build   # генерация *.g.dart (json_serializable и retrofit)
flutter run -d chrome
```

Тесты:

```bash
flutter test
```

Нужен Flutter с Dart SDK не ниже 3.8 и подключение к интернету (для первого запуска).

## Возможности

- Список постов: первая загрузка 10 штук, подгрузка следующих страниц при прокрутке, индикатор внизу, кнопка «Повторить» при ошибке подгрузки.
- Поиск по заголовку (среди уже загруженных постов, об этом написано в интерфейсе), фильтр по автору, сортировка по ID, сброс фильтров.
- Детали поста с комментариями.
- Создание поста: проверка полей до отправки, блокировка кнопки во время запроса, показ ответа сервера, добавление в локальный список с пометкой «создан локально».
- Кэш: сохранённые посты показываются сразу, свежие данные подгружаются следом. Обновление жестом pull-to-refresh.

## Архитектура

```
lib/
├── core/
│   ├── network/dio_client.dart      единый Dio, таймауты, LogInterceptor, заголовки, преобразование ошибок
│   └── error/app_exception.dart     типы ошибок (нет сети, таймаут, сервер, JSON, неизвестная)
├── data/
│   ├── models/                      Post, Comment, User (json_serializable)
│   ├── remote/post_api.dart         Retrofit: 4 GET и 1 POST
│   ├── local/post_cache.dart        кэш постов (shared_preferences)
│   └── repositories/post_repository.dart   сеть + кэш + превращение ошибок
├── presentation/
│   ├── screens/                     список, детали, создание поста
│   └── state/                       Bloc, события, состояния, Cubit'ы
└── main.dart
```

Слои:

| Слой | Задача |
|---|---|
| Presentation | Экраны и виджеты. Отправляют события в Bloc и рисуют по состоянию. К Dio не обращаются. |
| Repository | Единственная точка доступа к данным: берёт данные из сети или кэша, превращает любые сбои в `AppException`. |
| Remote data source | Retrofit-интерфейс и Dio с interceptor'ами. |
| JSONPlaceholder | Внешний REST API. |

### Запросы Retrofit

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/posts?_page=&_limit=` | страница постов (пагинация) |
| GET | `/posts?userId=` | посты автора |
| GET | `/posts/{id}/comments` | комментарии |
| GET | `/users` | список авторов |
| POST | `/posts` | создание поста |

### Состояния

Для списка: `loading`, `success`, `error`, `cached`, `empty`. Загрузка списка (`status`), подгрузка страницы (`isLoadingMore`), фоновое обновление (`isUpdating`) и отправка формы (`CreatePostStatus`) хранятся отдельно, один флаг `isLoading` на всё не используется.

### Обработка ошибок

Все ошибки превращаются в один тип `AppException` и его потомков: `NetworkException` (нет соединения), `TimeoutException`, `ServerException` (с кодом 4xx или 5xx), `ParsingException` (некорректный JSON) и общая ошибка для остального. Пользователь видит понятное сообщение, технические подробности остаются в логах (`LogInterceptor`).

## Поведение приложения

- **Первый запуск.** Кэша нет, показывается индикатор загрузки. Посты приходят с сервера, первая страница сохраняется в кэш.
- **Повторное открытие.** Сразу показываются сохранённые посты с жёлтой полосой «Показаны сохранённые данные, идёт обновление…». Параллельно идёт запрос на сервер, после успеха список и кэш обновляются, полоса пропадает.
- **Нет интернета.** Остаются сохранённые посты и полоса с текстом ошибки. Последний успешный результат не стирается. Если кэша нет, показывается экран ошибки с кнопкой «Повторить».
- **Создание поста.** Тестовый сервер принимает POST, но не хранит посты. Поэтому созданный пост добавляется только в локальный список и помечен «создан локально».

## Зачем нужны Dio, Retrofit, json_serializable и Repository

- **Dio** выполняет HTTP-запросы. Даёт единый клиент с таймаутами, логированием и interceptor'ами, чтобы настройки сети были в одном месте.
- **Retrofit** описывает запросы как обычный интерфейс (`@GET`, `@POST`) и сам генерирует код отправки, поэтому не нужно вручную собирать адреса и разбирать ответы.
- **json_serializable** генерирует превращение JSON в объекты и обратно, ручной парсер не нужен, а ошибки в именах полей находятся при генерации.
- **Repository** прячет источник данных от экрана. Экран просит «посты», а откуда они пришли (сеть или кэш) и как обработаны ошибки, знает только репозиторий.
- **Bloc** отделяет логику от интерфейса: экран отправляет события и рисует по состоянию, поэтому логику можно тестировать без запуска приложения.
